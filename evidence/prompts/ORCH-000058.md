ARCHITECTURAL OBJECTIVE
The runner is the reusable process-level orchestration loop that a later live milestone can actually launch.

The runner MAY be asynchronous and MAY call injected external-I/O ports supplied by its caller.
The runner itself MUST NOT contain hard-coded browser/GitHub credentials or hidden global side effects.
Importing the module must never start a process, timer, poller, or network/browser operation.

A. HOST INSTANCE IDENTITY
Require caller-supplied stable runtime identity at minimum:
- hostInstanceId using HOST-INSTANCE-* shape
- hostGenerationId using HOST-GEN-* shape
- projectId
- workerRole=executor
- nowMs supplied per iteration or by injected deterministic clock port
- polling configuration supplied explicitly.

Host identity is operational identity only.
It does not create Architect, worker, HUMAN_AUTH, lease, mutation, or retry authority.

B. INJECTED RUNTIME PORTS
Define one exact runner port contract sufficient for a future live host, including at minimum:
- readDurableSnapshot()
- acquireMutationLease(request)
- reconcileMutationLease(request) for ambiguous acquisition only
- releaseMutationLease(request)
- sendWorkerDelivery(request)
- sendArchitectTrigger(request)
- publishHostEvent(event)
- waitForNextPoll(delayMs, signal) or equivalent injected wait
- optional deterministic nowMs/clock injection.

The runner must validate required ports before running.
No hidden fallback implementation may contact external systems.

C. ITERATION CONTRACT
Expose a bounded one-iteration API, e.g. runPersistentHostIteration(input), that:
1. reads one durable snapshot through the injected port;
2. invokes the accepted automatic-dispatch-host lifecycle controller;
3. performs at most ONE mutation-capable transport action in that iteration;
4. publishes a bounded host event describing the observed state/action outcome;
5. returns an immutable independent iteration result.

The iteration must never spin internally waiting for browser/assistant output.

D. LEASE REQUEST DESCRIPTOR
Modify the accepted lifecycle controller only as needed so HOST_MUTATION_LEASE_REQUIRED returns a deterministic machine-readable requiredLease descriptor containing at minimum:
- actionKind: WORKER_DELIVERY or ARCHITECT_TRIGGER
- projectId
- holder registrationId/workerRole or host-bound holder identity as required by accepted lease schema
- messageId
- dispatchId
- milestoneId
- exact bounded resourceScope
- resourceScopeSha256
- mutationEnvelopeSha256
- target identity/port/conversation when applicable.

The descriptor is a request for a prerequisite lease only.
It does not create/acquire a lease and never sets mutationAuthorized=true.

E. LEASE ACQUISITION CHOREOGRAPHY
When lifecycle returns HOST_MUTATION_LEASE_REQUIRED:
1. call acquireMutationLease exactly once for that iteration;
2. if ACQUIRED with a valid exact MUTATION_LEASE record, re-evaluate the same durable lineage through the accepted lifecycle controller using that lease;
3. only if re-evaluation returns HOST_DELIVERY_READY or HOST_ARCHITECT_TRIGGER_READY may the runner call the corresponding transport port;
4. if DENIED/CONFLICT => no transport, no retry in same iteration;
5. if acquisition outcome is AMBIGUOUS/unknown => do NOT acquire again; call only the read-only reconcileMutationLease port once; if still unresolved => reconciliationRequired=true and no transport;
6. HUMAN_AUTH must never substitute for the lease.

No blind lease acquisition retry.

F. SINGLE-FLIGHT MUTATION
Within one runner instance:
- at most one mutation-capable transport call may be in flight;
- a worker delivery and Architect trigger may never be attempted concurrently;
- a second dispatch may not advance while the first lineage is waiting for worker result/Architect/reconciliation;
- SENT/consumed durable evidence always wins over local transient state.

The runner must not depend on in-memory state alone for exactly-once delivery.

G. TRANSPORT RESULT HANDLING
Injected transport ports return a bounded durable transport result contract.

For SENT:
- require durable result identity/state supplied by adapter;
- publish host event;
- release the exact lease once;
- return waiting/advanced state for next iteration;
- no same-iteration second send.

For AMBIGUOUS:
- never resend;
- require reconciliationRequired=true;
- publish host event;
- release the lease only if the adapter confirms a durable AMBIGUOUS result was recorded; otherwise keep/no-release and rely on lease expiry/reconciliation;
- no second mutation in the iteration.

For FAILED_BEFORE_SEND:
- attemptedSendCount must be 0;
- release the lease if safely acquired and exact;
- no retry in the same iteration.

If a transport adapter throws/returns an unknown state after mutation may have occurred:
- treat as AMBIGUOUS;
- no resend;
- no second mutation;
- do not blindly release an uncertain lease;
- return reconciliationRequired=true.

H. LEASE RELEASE SAFETY
releaseMutationLease may be attempted at most once after a safely known releasable outcome.
If release is ambiguous:
- do not issue a second release;
- publish/return leaseReconciliationRequired=true;
- next mutation remains blocked until durable lease state is reconciled.

Lease release never changes transport outcome and never authorizes retry.

I. PERSISTENT LOOP
Expose a persistent loop API, e.g. runPersistentHost(input), that:
- repeatedly invokes the bounded iteration API;
- uses the injected wait/poll port;
- accepts an AbortSignal or equivalent explicit stop signal;
- exits cleanly on stop;
- respects control suppression from each fresh durable snapshot;
- never caches a prior PRE_DISPATCH_ELIGIBLE, lease, control, baseline, delivery, worker-result, or Architect-trigger decision across iterations as current authority;
- never starts automatically on module import.

No unbounded internal recursion.
No parallel iterations.

J. CIRCUIT / FAILURE POLICY
Support caller-configured bounded consecutive-failure threshold.
Repeated adapter/protocol failures must yield RUNNER_CIRCUIT_OPEN (or equivalent machine state) and stop mutation-capable progress until a fresh durable/control state allows recovery.
Do not turn failures into retry authority.
