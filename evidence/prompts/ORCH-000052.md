HUMAN AUTHORITY DESIGN

A. RECORD TYPE / PROTOCOL
Support exactly:
- recordType: HUMAN_AUTH
- schemaVersion: "1.0"
- protocolFamily: ORCHESTRATOR_GITHUB

HUMAN_AUTH becomes supported in the existing compatibility registry.
MUTATION_LEASE and CURATOR_RESULT remain RESERVED/NOT_YET_SUPPORTED.

B. PURPOSE
HUMAN_AUTH is durable evidence that the declared Human Final Authority approved one bounded operation/scope.
It is prerequisite authority only where project policy requires it.
It NEVER substitutes for Architect dispatch/decision, worker registration, control state, mutation lease, or project identity.

C. REQUIRED IMMUTABLE RECORD FIELDS
Define an exact supported v1.0 top-level schema containing at minimum:
- recordType
- schemaVersion
- protocolFamily
- authorityId
- authorityRevision
- projectId
- approvedBy
- approvedRole = HUMAN_FINAL_AUTHORITY
- operationClass
- scope
- mutationEnvelopeSha256
- maxConsumptionCount
- consumptionCount
- state
- issuedAt
- expiresAt
- previousRecordSha256
- consumedBy

authorityId must use HUMAN-AUTH-* shape.
authorityRevision must be integer >= 1.
Initial revision requires previousRecordSha256=null.
Later revisions require a valid lowercase 64-hex previousRecordSha256.

D. OPERATION CLASS / SCOPE
Support a bounded operationClass enum sufficient for:
- DESTRUCTIVE
- PRODUCTION
- DEPLOYMENT
- BUSINESS_DATA
- INTEGRATION
- EXTERNAL_MUTATION
- EXCEPTION

scope must bind deterministic project/operation identity and may include:
- milestoneId
- messageId
- dispatchId
- resourceType
- resourceId
- environment
- tenantId
- mutationEnvelopeSha256

Do not require every optional target dimension, but validation must reject an empty/unbounded scope.
mutationEnvelopeSha256 at top level must equal the scope mutation-envelope hash.

E. STATE MODEL
Support:
- ACTIVE
- CONSUMED
- REVOKED
- EXPIRED

Rules:
- maxConsumptionCount integer >=1
- consumptionCount integer >=0 and <= maxConsumptionCount
- ACTIVE requires consumptionCount < maxConsumptionCount
- CONSUMED requires consumptionCount == maxConsumptionCount
- REVOKED never authorizes use
- EXPIRED never authorizes use
- expiresAt may be null; otherwise integer epoch milliseconds > issuedAt
- lifecycle evaluation uses caller-supplied nowMs; no wall-clock reads inside pure evaluator.

F. HUMAN IDENTITY
Validator/evaluator must accept expected caller context:
- expectedProjectId
- expectedHumanFinalAuthority

A record for a different project or approving human fails closed.
For this project, expected human is Rony Finster, but implementation must remain generic and caller-bound rather than hard-coded globally.

G. AUTHORIZATION-USE EVALUATOR
Add pure deterministic evaluator for a proposed operation request.
At minimum require:
- valid supported HUMAN_AUTH record
- state ACTIVE
- nowMs within expiry
- project exact
- approving human exact
- requested operationClass exact
- requested scope is equal to or narrower than authority scope under explicitly implemented deterministic rules
- requested mutationEnvelopeSha256 exact
- consumptionCount < maxConsumptionCount

Return machine-readable outcomes/reasons including:
- HUMAN_AUTH_AUTHORIZED
- HUMAN_AUTH_INVALID
- HUMAN_AUTH_PROJECT_MISMATCH
- HUMAN_AUTH_HUMAN_MISMATCH
- HUMAN_AUTH_SCOPE_MISMATCH
- HUMAN_AUTH_MUTATION_ENVELOPE_MISMATCH
- HUMAN_AUTH_EXPIRED
- HUMAN_AUTH_REVOKED
- HUMAN_AUTH_ALREADY_CONSUMED
- HUMAN_AUTH_OPERATION_CLASS_MISMATCH

No denied outcome authorizes mutation or retry.

H. IMMUTABLE CONSUMPTION TRANSITION PROJECTION
Add a pure deterministic function that, only after an AUTHORIZED evaluation, derives the next immutable HUMAN_AUTH record projection without mutating the input.

The derived record must:
- preserve authorityId/project/approvedBy/operationClass/scope/mutation envelope/max count/issuedAt/expiresAt;
- increment authorityRevision exactly +1;
- require caller-provided previousRecordSha256 matching lowercase 64-hex;
- increment consumptionCount exactly +1;
- set state CONSUMED when count reaches max, otherwise ACTIVE;
- append/record consumedBy identity containing exact messageId, dispatchId, milestoneId, workerRole, and result/operation reference as defined by implementation;
- remain independent/frozen-safe;
- never mutate/rewrite the prior immutable record.

This is a projection only. This milestone does NOT publish a live HUMAN_AUTH record.
