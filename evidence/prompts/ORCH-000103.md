REQUIRED SEMANTICS
1. Module import performs zero network/process/timer I/O.
2. getBranchHead returns the exact current branch commit SHA from GitHub.
3. readJsonAtRef(path, ref) reads that exact ref, decodes UTF-8 JSON, and returns both parsed value and the target file/blob SHA needed for CAS.
4. readJsonCurrent(path) captures a fresh branch head then reads the file at that exact ref; no mixed-ref result.
5. createJson(path, value):
   - performs one create-only GitHub Contents write on the configured branch;
   - unrelated branch advances must not create a non-fast-forward failure because no local parent push is used;
   - exact existing content may reconcile to IDEMPOTENT;
   - conflicting existing content must fail closed;
   - ambiguous external outcome gets at most one read-only reconciliation and no second mutation attempt.
6. updateJsonCas(path, expectedSha, value):
   - for non-null expectedSha, use the target file SHA as GitHub Contents API CAS;
   - unrelated branch advancement must not invalidate the operation when the target file SHA is unchanged;
   - changed/stale target SHA must fail closed without retry;
   - if expectedSha is null, implement create-only semantics or return a clear create-path outcome; never perform a local git parent-based push;
   - ambiguous external outcome gets at most one read-only reconciliation and no second mutation attempt.
7. Successful writes return statuses compatible with accepted github-runtime-ports expectations: CREATED / UPDATED / OK / IDEMPOTENT as appropriate; clear conflicts/denials remain non-success; unresolved ambiguity returns AMBIGUOUS.
8. Do not synthesize success from branch movement alone; exact target-path readback is required for reconciliation.
9. Do not include assistant text, browser DOM, credentials, tokens, authorization headers, or private business data in returned telemetry/errors.
10. No blind retry.
