ARCHITECTURAL OBJECTIVE
Add a pure/deterministic host lifecycle controller that can be called once per polling iteration by a future persistent process.

The controller does NOT itself perform GitHub/browser/process I/O.
All external observations/actions are caller-supplied/injected.
The controller decides the next legal host action and whether any mutation-capable action is eligible.

A. HOST STATE MODEL
Support explicit machine states at minimum:
- HOST_IDLE
- HOST_GOVERNANCE_DENIED
- HOST_MUTATION_LEASE_REQUIRED
- HOST_DELIVERY_READY
- HOST_WAITING_WORKER_RESULT
- HOST_WORKER_RESULT_READY
- HOST_ARCHITECT_TRIGGER_READY
- HOST_WAITING_ARCHITECT
- HOST_RECONCILIATION_REQUIRED
- HOST_CONTROL_SUPPRESSED
- HOST_CIRCUIT_OPEN

State must be derived from durable/current evidence supplied by caller, never from browser assistant text.

B. DISPATCH EXACTLY-ONCE / CONSUMPTION
The host must distinguish:
- no canonical unconsumed dispatch;
- a new canonical dispatch not yet delivered;
- an already SENT delivery for that dispatch;
- an AMBIGUOUS delivery requiring reconciliation;
- a terminal/consumed dispatch that must not be delivered again.

A SENT delivery for the current dispatch MUST move to WAITING_WORKER_RESULT and MUST NOT return delivery-ready.
An AMBIGUOUS delivery MUST move to RECONCILIATION_REQUIRED and MUST NOT authorize resend.
A consumed/terminal dispatch MUST NOT re-enter delivery readiness unless Architect creates a new dispatch identity.

C. GOVERNANCE BEFORE DELIVERY
For a new dispatch candidate, reuse the accepted ORCH-000055 candidate gate.
Do not duplicate project/profile/HUMAN_AUTH/MUTATION_LEASE validation.

A candidate may become HOST_DELIVERY_READY only when:
- canonical dispatch identity is current/unconsumed;
- worker registration/authority is exact and active;
- control state is clear;
- accepted baseline matches;
- candidate gate returns PRE_DISPATCH_ELIGIBLE;
- all existing transport-specific readiness checks pass.

If candidate gate denies, return HOST_GOVERNANCE_DENIED with exact governance reason and:
- deliveryEligible=false
- sendEligible=false
- mutationAuthorized=false
- retryAuthorized=false.

D. PERSISTENT-HOST MUTATION LEASE POLICY
This milestone establishes the policy for a future persistent host.

Any host action that would mutate a shared external BrowserRelay target, including:
- worker delivery send on 9444; or
- Architect doorbell send on 9333
MUST require mutationLeaseRequired=true.

The caller must supply a valid MUTATION_LEASE bound to the exact host/worker lineage, exact resource scope, exact dispatch/message/milestone, and mutation-envelope hash before the controller can return a mutation-ready state.

If a mutation-capable action is otherwise ready but the required lease is absent/denied/conflicting:
- state=HOST_MUTATION_LEASE_REQUIRED
- mutationAuthorized=false
- retryAuthorized=false
- no fallback to one-shot semantics.

The previously accepted ORCH-000056 mutationLeaseRequired=false exception applies ONLY to that manually invoked one-shot qualification and MUST NOT be generalized.

E. WORKER RESULT PHASE
After current delivery is durably SENT:
- if no newer valid worker result exists for the delivered message/dispatch => HOST_WAITING_WORKER_RESULT;
- if a matching valid unconsumed worker result exists => HOST_WORKER_RESULT_READY;
- stale result for another message/dispatch must not advance the host.

The controller MUST NOT parse worker assistant text from the browser.
Worker result authority is durable GitHub evidence only.

F. ARCHITECT DOORBELL PHASE
When a matching worker result is ready and no current Architect trigger has been sent for that result lineage:
- require control clear;
- require the persistent-host mutation lease for Architect target resource;
- require the already-accepted exactly-once Architect doorbell safety/correlation contract;
- then return HOST_ARCHITECT_TRIGGER_READY.

If an Architect trigger for the exact result lineage is already SENT => HOST_WAITING_ARCHITECT.
If trigger is AMBIGUOUS => HOST_RECONCILIATION_REQUIRED.
Never resend from the host merely because Architect has not responded.

The controller must never parse Architect assistant text.
