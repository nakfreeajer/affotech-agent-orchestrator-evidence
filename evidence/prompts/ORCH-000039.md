C. EXACTLY ONE WORKER SEND
After durable ARMED read-back, invoke the accepted worker browser-send adapter at most once.
Only the compact locator is sent.
Never send the canonical prompt body.

Result mapping:
- structural composer empty after the one send action => SENT
- timeout/non-empty/uncertain application => AMBIGUOUS
- pre-send failure => FAILED_BEFORE_SEND

For AMBIGUOUS:
- retryAuthorized=false
- next state=RECONCILIATION_REQUIRED
- no second send

Never read or parse worker assistant response DOM.

D. RESULT WAIT
Only after confirmed SENT:
- read durable GitHub worker-result evidence through the injected result adapter;
- require result binds expected workerRole/dispatchId/messageId/deliveryId where the result schema supports delivery binding;
- no result => RESULT_WAIT with no browser action;
- mismatched/invalid result => fail closed / reconciliation or circuit outcome;
- assistant response text/DOM is irrelevant.

E. ARCHITECT DOORBELL
Only after a valid new durable worker result:
1. prepare exactly one Architect-trigger intent using existing trigger authority/registration;
2. require durable trigger-intent read-back before send;
3. send exactly:

   to the registered Architect session;
4. at most one send action;
5. never read/parse Architect response DOM;
6. structural send confirmation only;
7. ambiguous trigger send => no blind retry, reconciliation required.
