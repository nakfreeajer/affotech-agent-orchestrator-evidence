AUTOMATIC WATCHER CONTRACT
Add a bounded, callable dispatch-watcher state machine for the local Orchestrator host.

The watcher must operate only from GitHub/Git evidence and explicit registration.
It must never derive authority from visible assistant text or DOM content.

Inputs must include at minimum:
- repoRoot
- ref, default origin/main
- registered workerRole
- worker registration/authority identity
- current watcher state
- poll result / captured Git ref

The watcher must use the accepted native Git-object resolver.
Canonical prompt bytes must never enter shell command strings, Base64 arguments, environment variables, or argv.
Use shell=false and bounded argument arrays only.

WATCH DECISION RULES
From one captured Git ref, read and verify:
- LATEST_DISPATCH
- immutable DISPATCH record
- LATEST_ARCHITECT_PROMPT
- LATEST_ARCHITECT_DECISION
- LATEST_EXECUTOR_ACCEPTED
- worker authority/registration
- RELAY_CONTROL
- relevant stop/pause/abort/reconciliation/circuit controls

The watcher may produce a delivery candidate only when all are true:
1. dispatch targetRole equals registered workerRole;
2. dispatch is explicitly in a relay-eligible state;
3. Architect decision explicitly authorizes the same messageId as current/next;
4. immutable dispatch and current pointers agree;
5. native resolver verifies canonical prompt SHA exactly;
6. no suppressing control is active;
7. no other worker delivery is currently ARMED or unresolved for the same dispatch;
8. this dispatch has not already been consumed by this watcher generation.

The watcher output is a PLAN only in this milestone.
It must not mutate GitHub or browser state.

DELIVERY CANDIDATE
For an eligible dispatch, return a structured candidate containing:
- dispatchId
- messageId
- workerRole
- workerAuthorityId
- workerRegistrationId
- capturedRef
- canonicalPromptPath
- canonicalPromptSha256
- deliveryPayloadKind = GITHUB_DISPATCH_LOCATOR_V1
- deliveryPayloadText
- deliveryPayloadSha256
- deliveryPayloadByteCount
- nextAction = PREPARE_DURABLE_INTENT

The browser payload remains exactly:
execute github dispatch <repository> <dispatchId>

The watcher must not include the canonical prompt body in deliveryPayloadText.

IDEMPOTENCY / EXACTLY-ONCE PREPARATION
Model watcher states at minimum:
- IDLE
- CANDIDATE_READY
- INTENT_REQUIRED
- IN_FLIGHT
- RESULT_WAIT
- RECONCILIATION_REQUIRED
- PAUSED
- CIRCUIT_OPEN

Rules:
- the same dispatch cannot produce two independent delivery candidates within one watcher generation after it is marked consumed/in-flight;
- an unresolved/AMBIGUOUS delivery forbids retry until a later Architect-authorized reconciliation explicitly resolves/supersedes it;
- a remote advance requires a new captured ref and re-evaluation;
- do not silently fall back to an older dispatch;
- one worker mutation stream at a time.
