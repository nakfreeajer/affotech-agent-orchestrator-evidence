PRE-DISPATCH GOVERNANCE DESIGN

A. PURE DECISION, NOT AUTHORITY CREATION
Add a dependency-light pure/deterministic evaluator.
It MUST NOT:
- create an Architect decision;
- create/consume HUMAN_AUTH evidence;
- create/acquire a mutation lease;
- mutate a dispatch/worker/control/profile/baseline record;
- perform a browser/GitHub/external mutation;
- turn a denied result into retry authority.

Its output is only a machine-readable eligibility decision for a proposed bounded dispatch context.

B. INPUT CONTRACT
Define an exact supported input object containing the evaluator context required to determine eligibility, including at minimum:

1. project profile / project validation input;
2. expected project/protocol identity;
3. canonical dispatch identity:
   - messageId
   - dispatchId
   - milestoneId
   - targetRole
   - canonicalPromptSha256
   - expectedAcceptedSourcePublicationId
   - expectedMutationEnvelopeSha256;
4. registered worker identity/state:
   - projectId
   - role
   - registrationId
   - active/inactive state;
5. current control state and applicable suppressions;
6. current accepted baseline identity:
   - acceptedSourcePublicationId
   - fileCount
   - manifest/archive identity as supplied by caller when required;
7. operation policy:
   - mutating boolean
   - operationClass
   - humanAuthorityRequired boolean
   - mutationLeaseRequired boolean
   - ambiguityProneExternalMutation boolean;
8. exact bounded mutation-envelope identity/hash and requested resources;
9. optional HUMAN_AUTH record plus deterministic nowMs when human authority is required;
10. external-mutation safety plan when ambiguityProneExternalMutation=true.

No wall-clock, filesystem, network, browser, GitHub, or process-state reads inside the evaluator.

C. PROJECT / PROFILE GATE
Use the accepted PROJECT_PROFILE validator rather than duplicating a conflicting project schema.

Require:
- valid supported PROJECT_PROFILE;
- caller expectedProjectId equals profile projectId;
- protocol family exact ORCHESTRATOR_GITHUB;
- protected/no-access boundaries respected;
- project profile does not itself grant dispatch/mutation authority.

Profile invalid/mismatch => fail closed.

D. DISPATCH / WORKER IDENTITY GATE
Require:
- messageId/dispatchId/milestoneId non-empty and exact caller expectations;
- canonical prompt SHA-256 valid lowercase 64-hex;
- expected mutation-envelope SHA-256 valid lowercase 64-hex;
- target role equals registered worker role;
- worker registration active;
- worker project equals profile project;
- accepted-source identity in dispatch equals current accepted baseline identity.

Any mismatch => fail closed.

Do not infer identity from browser text or worker self-report.

E. CONTROL GATE
Caller supplies current control state/applicable suppressions.

Fail closed when any applicable suppressing state is active, including project-policy equivalents of:
- PAUSED_BY_RONY / PAUSED_BY_HUMAN
- STOP
- ABORT_CURRENT_WORKER
- RECONCILIATION_REQUIRED
- CIRCUIT_OPEN

ACTIVE/clear state alone does not create authority; all other gates still apply.

F. MUTATION ENVELOPE GATE
If mutating=true:
- require a non-empty bounded mutation envelope;
- require its deterministic SHA-256 identity to equal dispatch expectedMutationEnvelopeSha256;
- reject unbounded wildcard/all-project mutation scope;
- reject requested access to profile-protected/no-access resources;
- reject requested AFFOTECH access/integration while self-profile flags remain false.

If mutating=false:
- evaluator may accept an explicitly empty/no-mutation envelope but must still enforce identity/control/profile gates.

G. HUMAN AUTHORITY GATE
If humanAuthorityRequired=false:
- do not invent or require HUMAN_AUTH;
- return humanAuthorityState=NOT_REQUIRED.

If humanAuthorityRequired=true:
- a valid HUMAN_AUTH 1.0 record is required;
- evaluate it using accepted HUMAN_AUTH logic with expected project/human, nowMs, operationClass, requested scope, and exact mutation-envelope SHA;
- require HUMAN_AUTH_AUTHORIZED;
- do not consume/project the authority in this validator;
- return humanAuthorityState=AUTHORIZED only as prerequisite evidence.

Missing/invalid/expired/revoked/consumed/scope/envelope/human/project mismatch => fail closed.

Human authority NEVER substitutes for Architect dispatch, worker registration, control state, or mutation lease.

H. MUTATION LEASE GATE
The accepted registry still marks MUTATION_LEASE RESERVED/NOT_YET_SUPPORTED.

If mutationLeaseRequired=false:
- return mutationLeaseState=NOT_REQUIRED.

If mutationLeaseRequired=true:
- fail closed with a distinct reason indicating mutation lease is required but not yet supported/validated;
- never treat HUMAN_AUTH, worker registration, or single-worker intent as an implicit lease.

This milestone must NOT implement MUTATION_LEASE.
That is the next architecture milestone after this validator is accepted.

I. AMBIGUITY-PRONE EXTERNAL MUTATION PLAN
If ambiguityProneExternalMutation=false:
- return externalMutationSafetyState=NOT_REQUIRED.

If true, require a deterministic declared plan proving the proposed operation will use:
- read-only pre-attempt target snapshot/boundary;
- durable intent before mutation;
- exactly one mutation attempt;
- durable result or AMBIGUOUS;
- read-only reconciliation before any retry;
- durable target-bound correlation identity/payload-or-mutation hash;
- explicit no-blind-retry rule.

Missing/incomplete plan => fail closed.
The validator validates plan declaration only; it performs no external mutation.
