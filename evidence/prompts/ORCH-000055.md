C. FAIL-CLOSED CANDIDATE STATES
A discovered candidate MUST NOT become delivery-ready merely because:
- its DISPATCH exists;
- its prompt hash matches;
- the worker registration is active;
- HUMAN_AUTH exists;
- MUTATION_LEASE exists;
- the watcher previously would have returned CANDIDATE_READY.

Require accepted pre-dispatch outcome PRE_DISPATCH_ELIGIBLE before delivery readiness.

If governance is missing, malformed, mismatched, suppressed, protected-resource conflicting, HUMAN_AUTH denied, MUTATION_LEASE missing/denied, or external-mutation plan incomplete:
- deliveryEligible=false;
- sendEligible=false;
- retryAuthorized=false;
- browserContactAuthorized=false;
- candidateState=CANDIDATE_GOVERNANCE_DENIED;
- preserve the accepted pre-dispatch reason code in a machine-readable field such as governanceReason;
- do not downgrade denial into a generic candidate-ready state.

Missing governance context fails closed.
No legacy/fallback path may bypass the gate.

D. ELIGIBLE CANDIDATE
When the accepted pre-dispatch validator returns PRE_DISPATCH_ELIGIBLE:
- candidateState may proceed to the existing watcher-ready state (preserve the canonical existing ready-state spelling if one exists);
- governanceState=PRE_DISPATCH_ELIGIBLE;
- deliveryEligible may reflect the existing candidate readiness rules;
- mutationAuthorized MUST remain false;
- retryAuthorized MUST remain false unless a separate later transport contract explicitly authorizes retry (this milestone must not create such authority);
- HUMAN_AUTH is not consumed;
- MUTATION_LEASE is not acquired/released/modified;
- no external mutation occurs from the governance gate itself.

The candidate still must pass all existing transport-specific rules before any later send milestone.

E. READ-ONLY VS MUTATING OPERATIONS
Read-only/non-mutating candidate:
- may be eligible with humanAuthorityRequired=false and mutationLeaseRequired=false when all other gates pass.

Mutating candidate:
- must carry a bounded matching mutation envelope;
- HUMAN_AUTH is required only when the caller operation policy says humanAuthorityRequired=true;
- MUTATION_LEASE is required only when caller operation policy says mutationLeaseRequired=true;
- a valid lease cannot substitute for HUMAN_AUTH;
- HUMAN_AUTH cannot substitute for a lease;
- neither can bypass control/project/baseline/protected-resource/external-plan gates.
