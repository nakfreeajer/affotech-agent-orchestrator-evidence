ARCHITECT DECISION

The previous design became over-engineered by using GitHub relay/evidence pointers as the runtime message bus.

Replace that control-loop design with a local-first Orchestrator.

GitHub is NOT part of the normal runtime control loop.
GitHub may remain optional for source push, accepted-milestone evidence, backup, or release history only.

The normal control loop must work when GitHub is unavailable.

GOAL

Implement the simplest reliable local loop:

LOCAL PYTHON
-> launches one Codex Executor child
-> monitors the real child process
-> persists the completed Executor report locally
-> captures local repository state
-> sends the completed local report to the Architect browser
-> monitors Architect generation locally through CDP
-> reads the finalized Architect response
-> extracts one bounded machine-readable Architect envelope
-> if a next Executor prompt exists, persists it locally
-> launches the next Codex child exactly once
-> repeats

Rony or ChatGPT must not manually copy/publish the normal next prompt.

CORE PRINCIPLE

One PC.
One Python Orchestrator.
One Architect browser session.
One Codex Executor child at a time.

Do not build distributed-system machinery around this local workflow.

==================================================
EXECUTOR PROCESS CONTROL
==================================================

Python must own the Codex child process.

When Python launches Codex, persist:

- PID
- target repo
- local result path
- state=EXECUTOR_RUNNING

While the child is alive:

- elapsed time is irrelevant;
- do not trigger Architect;
- do not launch another Codex child;
- do not classify failure because of stderr ERROR text alone.

Completion authority is actual process exit.

After restart:
- if saved PID still belongs to the expected Codex child, remain EXECUTOR_RUNNING;
- if PID no longer exists, reconcile the saved result file/process exit before doing anything else;
- never rerun merely because Python restarted.

Exactly one live Codex writer maximum.

==================================================
EXECUTOR RESULT
==================================================

The Executor final response must be persisted locally by Python.

Prefer launching Codex with a deterministic local `--output-last-message` path inside the local orchestrator result directory rather than a volatile Temp path, if supported by the installed CLI.

If the CLI requires another mechanism, copy the completed final message into the durable local result path immediately after actual process exit.

A result is RESULT_READY only when:
- child has actually exited; and
- the expected result file exists and is non-empty.

If child exits without a usable report:
- state=EXECUTOR_CRASHED;
- do not invent a report;
- do not rerun automatically;
- require bounded recovery/human decision.

Also capture local target-repository evidence after exit:
- git status --porcelain
- HEAD
- changed-file summary
- optional test/commit information already stated in the Executor report

Dirty files are supporting evidence, not completion authority.

Do not require GitHub to know what the local Executor did.

==================================================
ARCHITECT MACHINE-READABLE ENVELOPE
==================================================

The message sent to Architect must require that every completed Architect response end with exactly one envelope:

<ORCHESTRATOR_RESULT>
classification=ACCEPTED|BLOCKED|INCONCLUSIVE|NO_NEW_REPORT
action=EXECUTE|HUMAN_REQUIRED|STOP
taskId=<completed task id>
promptBegin
<complete next Executor prompt only when action=EXECUTE>
promptEnd
</ORCHESTRATOR_RESULT>

Rules:
- `action=EXECUTE` requires a non-empty complete prompt.
- `action=HUMAN_REQUIRED` and `action=STOP` require an empty prompt body.
- taskId must match the completed Executor task.
- Python parses only this final envelope for automation.
- Architect may provide normal human-readable explanation before the envelope.
- Python must not infer a next task from prose outside the envelope.
- malformed/missing envelope => keep a recoverable Architect-result error state and do not launch Codex.
- duplicate identical finalized Architect response must not create a duplicate child.

No GitHub publication is required for this handoff.

==================================================

For action=STOP:

- do not launch Codex.
